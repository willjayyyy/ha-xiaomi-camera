# 小米摄像头 · Home Assistant

[English](README.md) | **简体中文**

在 Home Assistant 里看到你的小米摄像头画面。

小米官方的集成会给出摄像头的传感器和按钮，唯独没有画面。本项目补上画面 ——
既是 Home Assistant 里普通的摄像头实体，也是标准的 RTSP 流，
Frigate、Scrypted 或任意 NVR 都能直接用。

- 摄像头自动出现，名称和房间沿用米家 App 里的设置
- 实时画面、快照、录像，和其他摄像头没有区别
- 画面不出你自己的网络

## 开始之前

- **Home Assistant 2024.11 或更新版本**，运行在 64 位系统上
- **Home Assistant 必须和摄像头在同一个网络里。** 这一条没有变通余地 ——
  [原因见下](#为什么必须在同一个网络)
- 摄像头已经在米家 App 里添加好

## 安装

一共两个部分，同一个仓库地址要在 Home Assistant 的两个地方分别添加。
只做一个的话，功能是不完整的。

**1. 把仓库添加到加载项商店**

设置 → 加载项 → 加载项商店 → ⋮ → 仓库，粘贴：

```
https://github.com/willjayyyy/ha-xiaomi-camera
```

这一步不需要你安装任何东西，只是让它变得可用。

**2. 通过 HACS 安装集成**

在 HACS 里把同一个地址添加为自定义仓库（类型选 *集成*），
然后安装 **Xiaomi Camera**。装完重启 Home Assistant。

**3. 添加集成**

设置 → 设备与服务 → 添加集成 → **Xiaomi Camera**。

它会提示帮你安装取流服务，需下载约 180 MB，请耐心等待几分钟。

装好之后打开它的页面登录小米账号，几秒钟后摄像头就会出现。

## 关于登录

登录后，小米会将浏览器重定向到一个**无法打开的地址**，出现空白页或报错属于
正常现象。复制地址栏中的完整地址，粘贴回加载项页面即可完成登录。

## 选择视频流

每台摄像头可以发布同一画面的多个版本，在集成选项的 **视频流** 中按摄像头选择。

| 视频流 | 适用场景 |
|---|---|
| H.265 · 原始画质 | 录像、NVR 软件。摄像头原生编码，不经转码。 |
| H.264 · 原始画质 | 无法解码 H.265 的浏览器和播放器。 |
| 360p / 180p | Apple 家庭、远程查看、同屏显示多路画面。 |
| 720p | 摄像头分辨率更高时的折中选择。 |

摄像头默认提供原始编码。如果浏览器放不出画面，请添加一路 H.264——多数浏览器
无法解码 H.265。

**Apple 家庭：** 添加一路 360p，并让 HomeKit 桥接指向该实体。Home Assistant
会按 HomeKit 指定的码率重新编码，而该码率很低，因此画面尺寸小反而更清晰。
请不要勾选「支持原生 H.264 流的摄像机」（*Cameras that support native H.264
streams*）。

## 不用 Home Assistant 也能跑

取流服务本身是完整独立的：它连接摄像头并发布 RTSP，Home Assistant 只是众多消费方
之一。如果你只想要视频流 —— 给 Frigate、Scrypted、NVR，或任何能读 RTSP 的东西 ——
可以单独运行同一个镜像。

所有东西都留在本机时，不需要任何密码：

```bash
docker run -d --name xiaomi-camera \
  --network host \
  -v xiaomi-camera:/data \
  ghcr.io/willjayyyy/addon-xiaomi-camera-bridge:latest
```

此时所有监听都绑在 `127.0.0.1`，别的机器根本连不上来。打开页面用 SSH 隧道 ——
`ssh -L 8098:127.0.0.1:8098 用户@主机`，然后访问 `http://127.0.0.1:8098` ——
在那里连接小米账号。

要让其他机器读取视频流，就得把它发布出去。这是唯一会改变安全模型的设置，
因此它连带要求配套的密码，缺任何一项服务都不会启动：

```bash
docker run -d --name xiaomi-camera \
  --network host \
  -v xiaomi-camera:/data \
  -e XIAOMI_CAMERA_ACCESS_MODE=lan \
  -e XIAOMI_CAMERA_RTSP_USERNAME=xiaomi \
  -e XIAOMI_CAMERA_RTSP_PASSWORD=... \
  -e XIAOMI_CAMERA_WEB_PASSWORD=... \
  ghcr.io/willjayyyy/addon-xiaomi-camera-bridge:latest
```

之后视频流地址是 `rtsp://<主机>:8554/camera_<设备 id>`，页面 `http://<主机>:8098`
上会列出每台摄像头的完整地址。所有配置项都能这样传：`XIAOMI_CAMERA_` 加上大写的
选项名。

`-v xiaomi-camera:/data` 不是可选项。小米账号的授权存在这里，不挂的话每次更新
（更新即重建容器）都会要求你重新授权小米账号。检测到这种情况时，服务会在日志里
给出警告。

有两点和作为加载项运行时完全一样：

- **必须 `--network host`**，原因和加载项一致：摄像头靠广播发现、点对点直连，
  这两件事都过不了 Docker 的 bridge 网络。
- **这台机器必须和摄像头在同一局域网**。VPN 不算。

另外有一点需要说清楚：这个页面走的是普通 HTTP，密码在网络上是可被旁观者读到的，
和 RTSP 凭据的暴露程度一样。如果你的部署环境在意这一点，请在前面加一层带 TLS
的反向代理。

## 为什么必须在同一个网络

小米摄像头是设备之间直接连接的，不经过服务器中转，
而找到它依赖于处在同一个局域网内。

如果 Home Assistant 在别的地方，连接要么退化成把画面经小米服务器转发 ——
更慢、画质更差，而且画面离开了你家 —— 要么干脆连不上。

**VPN 不算同一个网络。** 我们实测过：经 VPN 连接会彻底失败，
而在同一网络下，摄像头大约 2 秒就能连上。

## 摄像头可能"在线但关着"

小米摄像头的镜头开关和联网是两回事。镜头关着的时候，摄像头会正常应答，
然后**一点画面都不发** —— 看起来和坏掉了一模一样。

加载项页面和 Home Assistant 都会明确显示这个状态，
并且会给你一个开关实体，这样自动化可以在拍快照之前先把摄像头打开。

## 设置项

| 设置 | 默认 | 作用 |
|---|---|---|
| 画面访问范围 | `local` | `local` 让画面留在 Home Assistant 所在的机器上。`lan` 会分享给整个局域网供 Frigate 之类的工具使用，此时必须设置用户名和密码。 |
| RTSP 用户名 / 密码 | — | 访问范围选 `lan` 时必填 |
| 画质 | `low` | 仪表盘上看足够了。画质越高越占带宽。 |
| 包含声音 | 关 | 同时传输摄像头的声音 |
| 日志级别 | `info` | 反馈问题前调到 `debug` |
| 网页密码 | — | 访问范围为 `lan` 时必填。其他情况可不填，但**只要设置了就一定会校验**，通过 Home Assistant 面板进入时也一样。 |

## 隐私

默认情况下，**画面不会离开 Home Assistant 所在的那台机器**。
Home Assistant 可以显示，局域网上的其他设备无法访问。
这是初始配置，无需额外设置。

如果你想让另一台机器也用这些画面，把访问范围切换成 `lan`。
那会把画面分享给整个局域网，所以用户名和密码变成必填 ——
没填的话加载项不会启动，因为一个没有密码保护的摄像头画面，
在局域网里几秒钟就会被扫描到。

你的小米账号凭据只保存在加载项自己的私有存储里，
写日志和报错信息之前也会先把它们抹掉。

有一点不在本项目控制范围内：如果你把 Home Assistant 本身暴露到公网上，
那无论这里怎么设置都是有风险的。

## 哪些摄像头能用

支持范围以小米自己的名单为准，其中排除了大部分 2022 年之前的机型。
不支持的摄像头不会显示出来，而不是变成一个永远用不了的东西。

这并非出于保守：我们实测过一台被小米排除的机型，确实无法建立连接。
未出现在列表中的摄像头，基本可以确定在该名单上。

## 已知限制

- 摄像头输出 H.265 画面。其余所有视频流版本都是由此转换而来，
  且仅在有人观看时才会转换。
- 只测试过小米中国区账号。
- 没有双向语音、云台控制和 SD 卡回放。

## 故障排查

**未列出任何摄像头** —— 请确认加载项页面已连接账号，且这些摄像头位于
同一账号的米家 App 中。

**摄像头显示「已关闭」** —— 请在米家 App 中或通过开关实体打开镜头。

**摄像头显示「就绪」但无画面** —— 多为 Home Assistant 与摄像头不在
同一网络，参见上文。

反馈问题前请把日志级别调到 `debug`，并附上日志。
